# 模拟交易挂单撮合与持仓查询设计

## 目标

让模拟交易服务端按 A 股交易时段自动处理挂单，并把 SQLite 中的账户、持仓、
冻结资金和委托状态作为唯一事实来源。Agent 只负责分析和发出指令，不负责保存或
计算账户状态。

## 时间口径

- 所有撮合时间统一使用 `Asia/Shanghai`。
- 仅用系统日期排除周六、周日；法定节假日由 Agent 调用市场信息工具判断。
- 普通市价单和限价单只在 `09:30:00-11:30:00`、`13:00:00-15:00:00`
  撮合，起止时刻均包含。
- `auction_only` 委托只在 `09:20:00-09:25:00` 撮合，起止时刻均包含。
- 后台保持每 30 秒扫描一次待处理委托。

## 委托生命周期

### 普通当日委托

- 下单后状态为 `pending`。
- 限价买入在行情价小于或等于委托价时整笔成交。
- 限价卖出在行情价大于或等于委托价时整笔成交。
- 市价单在下一个有效撮合轮次按当次行情价整笔成交。
- 当日超过 `15:00:00` 后仍未成交时变为 `expired`，并释放冻结资金或冻结持仓。

### 集合竞价委托

- `auction_only` 委托可提前创建，但只在 `09:20:00-09:25:00` 检查成交条件。
- 当日超过 `09:25:00` 后仍未成交时变为 `expired`，并释放冻结资源。
- 首版继续使用 TDX 当次行情价判断，不模拟交易所集合竞价撮合算法。

### 服务重启

- SQLite 持久化保存 `pending` 委托。
- 每轮撮合先处理已过期委托，再请求行情撮合仍有效的委托。
- 因停机错过失效时间的委托在服务恢复后首先失效，不允许隔日错误成交。

## 行情与成交

- 每笔有效待处理委托通过现有 TDX 行情方法获取当前价格。
- 行情获取失败时保留 `pending`，等待下一轮；不得凭旧价格成交。
- 不支持部分成交，一笔委托只能整笔成交或继续等待。
- 成交价使用该轮获取的行情价。
- 同一股票存在多笔委托时，首版维持逐笔请求；出现实际限流或性能问题后再增加
  同轮行情缓存。

## 持仓查询

- `tdx_paper_portfolio(view=positions, accountId=...)` 返回指定账户的实时 SQLite
  持仓、可卖数量和冻结数量。
- 当日买入数量保持不可卖；服务启动时以及上海日期变化时，服务端根据持仓流水自动
  刷新 T+1 可卖数量，同时保留挂单已冻结的持仓。
- 持仓列表不返回 `quantity=0` 的已清仓记录；历史清仓数据继续从
  `closed_positions` 查询。
- 每个 Agent 必须固定对应的 `accountId`。
- Agent 在交易决策前应查询 `positions` 和 `orders`；服务端下单时仍校验实际可用
  资金与可卖持仓。
- 更新 MCP 工具说明，使上述调用顺序对 Agent 可见。

## 状态与审计

- 新增委托状态 `expired`，与用户主动撤单的 `cancelled` 区分。
- 自动失效必须记录 Agent 行为日志，并注明失效原因。
- 资金、持仓、委托状态和行为日志在同一数据库事务中更新，失败时整体回滚。

## 测试范围

- 普通限价单在交易时段达到价格后成交。
- 普通委托在非交易时段不成交。
- `day` 委托收盘后自动失效并释放冻结资源。
- `auction_only` 只在 `09:20:00-09:25:00` 撮合，超时后自动失效。
- 隔日遗留委托先失效，不会被新行情撮合。
- 当日买入保持不可卖，次日自动转为可卖。
- 持仓查询过滤零持仓。
- MCP 工具说明明确要求交易前查询持仓和委托。

## 明确不做

- 不实现逐笔成交回放、盘口排队和部分成交。
- 不在服务端评估交易价值或生成买卖决策。
- 不新增节假日日历数据库。
- 不改变现有 30 秒撮合轮询周期。
